Master Prompt — Quiz (LISM AI Classroom)
Fill in the bracketed fields, then paste this whole prompt into ChatGPT, Claude, Gemini or any AI tool.
Save the HTML it returns as a .html file and upload it to LISM AI Classroom.

Fill in: [TOPIC NAME] · [SUBJECT] · [GRADE] · [WEEK X]

Build a single self-contained interactive HTML quiz for [TOPIC NAME] — [SUBJECT], Grade [GRADE], Week [WEEK X].
One HTML file. Inline CSS and JS only, no external assets, no build step, no markdown fences in your reply.
It must open and work correctly by double-clicking the file, offline, with no LISM present — and work as a
teacher-paced activity when uploaded to LISM.

A scored quiz mixing question formats, checking understanding across the whole topic.


1. SUBJECT PROFILE (set this first — it drives layout, language and validation)

State this config object at the top of the file and make every part of the activity obey it. Infer
sensible values from [SUBJECT] and [TOPIC NAME]:

const PROFILE = {
  subject:'[SUBJECT]', grade:'[GRADE]', week:'[WEEK X]', topic:'[TOPIC NAME]',
  lang:'en',      // 'en' | 'ar' | 'fr' | 'es' | 'ur' | 'hi' — language of instruction
  dir:'ltr',      // 'rtl' for Arabic and Urdu — mirrors the whole layout
  math:false,     // true → maths rendering + symbol palette
  chem:false,     // true → chemical formula handling
  code:false,     // true → code editor behaviour
  images:true     // true → allow image attachment where it makes sense
};

2. LANGUAGE, SCRIPT AND RTL — ALL SUBJECTS INCLUDING ARABIC (mandatory)

This activity must work in any subject and any language the school teaches, Arabic included.

- Set <html lang> and dir from PROFILE. When dir:'rtl', mirror the ENTIRE layout — headers, progress
  indicators, buttons, cards, tables and badges all flow right-to-left. Next moves left, Previous moves
  right visually, but arrow keys keep their logical meaning.
- Keep numbers, formulae and code in dir:'ltr' islands inside RTL text so they do not reverse.
- Arabic normalisation before comparing any answer: strip tashkeel/diacritics, remove tatweel (ـ),
  unify alef (أ إ آ ٱ → ا), ى → ي, ة → ه, unify hamza forms, and convert Arabic-Indic digits
  (٠١٢٣٤٥٦٧٨٩) to Western digits. "الْمَاء" and "الماء" must both be accepted.
- Script-aware counting: count words for Arabic, Urdu and Hindi properly; for Chinese/Japanese use
  characters ÷ 2. Never use a Latin-only regex to judge length.
- Never apply an English vowel-based gibberish test to non-Latin script. For those, detect only
  repeated-character runs and single-character spam.
- French/Spanish/Urdu: accent-insensitive comparison for short answers, correct accents kept in the
  model answers.
- All on-screen instructions, buttons and feedback appear in PROFILE.lang. For a bilingual class, show
  the term and its translation together.
- Use a font stack that renders Arabic correctly and set a comfortable line-height for Arabic script.

3. ACCESSIBILITY AND DEVICE SUPPORT

Readable on a smart board and on a phone. Font sizes with clamp(), single column below 900px, touch
targets at least 44px, inputs at least 16px so iOS does not zoom. Full keyboard operation, visible
focus rings, and colour never used as the only signal. Nothing overlaps at any width.

4. STRUCTURE

Eight questions, one per section, then a results section.

Mix the formats deliberately: multiple choice, true/false with justification, short answer, one
numeric (if the subject suits it), and one ordering or matching item. Rise in demand from recall to
application to analysis across the eight.

Each question: immediate specific feedback, the correct answer shown only after the attempt, and a
running score. Wrong options must be plausible misconceptions, never filler.

Results section: score out of 8, which questions were missed, and one sentence per missed question
explaining the idea to revisit. Label it "estimated — your teacher's mark is final" if any question is
open-ended.

Use exactly these stage ids and order. Give the matching section in the HTML a data-stage="<id>"
attribute. If your activity genuinely needs more or fewer sections (for example a different number of
cards or puzzles), keep the same naming pattern and list every one of them in the manifest.

B. Detect LISM with `window.parent !== window`. When it is absent, run normally and self-paced.
   When present, hand pacing to the teacher and listen for
   {type:'lism:command', command, ...}:
     start_stage (stage) -> show ONLY that section, enable its inputs
     stage_ended         -> show "Waiting for your teacher…", disable that section
     pause / resume      -> freeze / unfreeze, never losing typed work
     lock (reason) / unlock
     set_config (copyPasteProtection, focusMonitoring, maxWarnings)
        -> when copyPasteProtection is on, block copy, cut, paste and right-click INSIDE ANSWER
           BOXES ONLY, never page-wide
     time_update (elapsedSeconds) -> store it; never render your own countdown, LISM shows the timer
   Ignore any unrecognised command silently. Never throw.

C. STUDENTS MUST SEE ONLY THE SECTION THE TEACHER HAS STARTED. Hide every other section until its
   start_stage arrives. Never auto-advance, and never reveal a later section early.

D. NO TIMERS OF YOUR OWN. No countdowns, clocks, progress rings, or time-based locking or advancing.
   The recommended duration is metadata in the manifest and may be printed as text beside a section
   title. LISM shows the one synchronised countdown.

E. Report every accepted answer to the teacher's live dashboard:
   window.parent.postMessage({type:'lism:event', event:'student_submitted',
     stageId, questionId, correct, answer, mark, maxMark, keywordsUsed}, '*')
   ALWAYS include `answer` with the student's actual text or choice — the teacher reads it aloud for
   feedback, and sending only `correct` leaves them nothing to discuss.
   Also emit activity_ready on load, stage_viewed when a section is shown, and activity_completed at
   the end with the final score.

F. Teacher preview: when the URL contains ?preview=1, show Previous/Next and a section counter, allow
   every section to be viewed in any order, and emit NO events at all.

G. Nothing is uploaded anywhere. Answers travel only via postMessage to the LISM page that embeds the
   activity. Opened standalone, nothing leaves the device at all.


MARKS

The manifest above already carries this activity's marks. Do not change the totals — LISM adds them up,
shows them to students, and puts them in the teacher's gradebook.

Each marked section declares three things:
  "marks"     what the section is worth in total
  "autoMarks" the part this activity can score by itself
  "rubric"    what each part is awarded for

Fill in every [square-bracket] descriptor in the rubric with wording specific to [TOPIC NAME] at Grade
[GRADE]. "Explains clearly" is not a descriptor — say what a correct explanation of THIS content must
contain.

WHAT YOU MAY SCORE AUTOMATICALLY: a chosen option, a matched pair, a placed item, a completed word, a
numeric answer, a passing test. Report these with `correct` and, when you know it, a numeric `mark` in
the student_submitted payload — never more than that section's autoMarks.

WHAT YOU MUST NOT SCORE: extended writing — explanations, justifications, reasoning. Send the student's
text and leave `correct` as null. The teacher awards those marks after reading the work, usually after
discussing it with the class. Keyword-matching an explanation would score a student who writes the right
idea in their own words as wrong, and reward one who sprinkles in the right nouns.

TELL THE STUDENT: on any marked section show "N marks — your teacher will see and review this". Do NOT
promise a grade or display a final total: the teacher decides whether and how to mark it, and a student
promised a number that never arrives stops believing the message.


EDUCATIONAL QUALITY (mandatory — this decides whether the activity is usable in a real classroom)

Every question must be about THIS topic's actual content. If a question would still make sense with a
different topic swapped in, it is not specific enough — rewrite it.

BANNED, because they assess nothing:
- "What do you remember about X?" / "What do you already know?"
- Options written as descriptions ("a correct statement", "a distractor", "a common misconception")
- "True or false: X always works the same way"
- Restating the topic name as if it were an answer

REQUIRED — choose the verb that fits the content: analyse this diagram/data · predict what happens
when… · explain why… · identify the error · classify these · interpret this graph · compare these two
cases · complete the missing step · label the diagram · order these steps · correct this misconception
· justify which explanation is better.

Every wrong option must be a real mistake a student at this grade actually makes — a specific wrong
value, a confused term, a step in the wrong order. If you cannot write plausible wrong answers for this
content, use an open response instead. Pitch the vocabulary, numbers and context to Grade [GRADE].

FEEDBACK: every response gets specific feedback that says how to improve, never just "wrong". Show the
correct answer only after the student has attempted it.
